# Goal, authority, and completion drift

Load this card only after an observed goal-preservation failure. It supplements the selected workflow; it cannot revise its checkpoint or assured contract.

## Activate on evidence

- Plans, reports, hashes, tests, checkers, gates, or orchestration work are starting to replace the requested product.
- The Agent treats its own additions as repository authority, or proposes removing user-owned work while cleaning up its additions.
- A correction invalidates an earlier assumption, but downstream plans or changes still depend on it.
- A completion claim is being prepared while the requested behavior is not directly observable.

## Minimum response

1. Restate one concrete deliverable and its external authority source. Separate it from supporting evidence.
2. Mark every Agent-created plan, report, hash, test, checker, gate, and generated policy as `supporting`; it has no authority to amend scope, non-goals, acceptance, or cleanup ownership.
3. Before creating new governance or verification machinery, apply `not-needed -> reuse -> stdlib -> native -> existing-dependency -> minimal-custom`. Add it only when a frozen acceptance item cannot be observed without it.
4. When the user corrects a material premise, list the downstream decisions and edits that depended on it. Revalidate or remove them before continuing.
5. Cleanup removes only Agent-created work unless the externally authorized scope explicitly includes user-owned work.

## Completion evidence

Show the requested product outcome first, then the proportional checks that support it. A passing test, complete report, valid digest, or finished task DAG is not a substitute for the product. If the product is absent or an acceptance item is false, report `incomplete` or the exact blocker.

## Boundary

This card reduces process drift. It cannot correct a model or runtime that ignores instructions, and it never upgrades practical evidence into an assured claim.
